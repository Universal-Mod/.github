# Contributing to UMOD
Discuss a proposed change with the team before starting a large feature. Developers receive access to the projects they work on. Use your own GitHub account.

Use one issue for each reproducible bug or proposed feature. Include the exact product version and whether the problem occurs in single player, multiplayer, a dedicated server, a headless client, or Zeus.

Work in a short-lived feature or fix branch. Open a pull request with the problem, change, testing evidence and limitations. A maintainer reviews it before merging or releasing. Do not publish development builds, change project licensing, remove original credits or include private credentials.

Public release notes describe player-visible changes. Private development discussions and unfinished work stay in private repositories. Report sensitive security issues through the private support route on https://umod.rocks or universalmodsupport@gmail.com.
